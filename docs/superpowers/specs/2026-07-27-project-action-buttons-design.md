# 프로젝트 카드 이중 버튼 설계

## 목표

네 개의 프로젝트 카드에 동일한 두 버튼 구조를 적용한다. 왼쪽 버튼은 GitHub 저장소를 열고, 오른쪽 버튼은 배포된 프로젝트를 연다. 아직 배포 주소가 없는 프로젝트는 준비 중 안내를 표시하며, 나중에 데이터의 URL만 교체하면 외부 링크로 전환되게 한다.

## 데이터 구조

각 프로젝트 데이터는 기존의 단일 `href`와 `linkLabel` 대신 다음 두 값을 가진다.

- `githubUrl`: GitHub 저장소 주소. 네 프로젝트 모두 필수다.
- `projectUrl`: 실행 가능한 배포 주소. 준비 중인 경우 `null`이다.

프로젝트별 연결은 다음과 같다.

| 프로젝트 | GitHub | 프로젝트 확인 |
|---|---|---|
| Trading | `https://github.com/Y-youngchan/Trading` | `https://trading-lake-ten.vercel.app/` |
| 영화 예매 사이트 | `https://github.com/Y-youngchan/movie_260407` | 준비 중 (`null`) |
| 계절별 감기약 수요 예측 | `https://github.com/Drug2026/Drug_main` | `https://huggingface.co/spaces/yyc1327/DrugMain` |
| 북스토어 | `https://github.com/Y-youngchan/bookstore` | 준비 중 (`null`) |

## 화면 동작

각 카드 하단에 다음 순서로 버튼을 배치한다.

1. 왼쪽: `GitHub에서 프로젝트 보기`
2. 오른쪽: `프로젝트 확인하기`

`projectUrl`이 있으면 오른쪽 버튼은 새 탭에서 해당 주소를 연다. `projectUrl`이 `null`이면 같은 모양의 버튼을 유지하고, 클릭 시 `프로젝트 페이지를 준비 중입니다.`라는 안내 팝업을 표시한다.

모바일 화면에서는 기존 카드 폭 안에서 버튼이 읽기 쉽도록 줄바꿈을 허용한다.

## 컴포넌트 경계

준비 중 클릭 동작은 브라우저 기능이 필요하므로 작은 클라이언트 컴포넌트로 분리한다. 프로젝트 목록과 본문 페이지는 현재 서버 컴포넌트 구조를 유지한다.

클라이언트 컴포넌트는 URL 유무에 따라 다음 중 하나를 렌더링한다.

- URL 있음: 안전 속성이 포함된 외부 링크
- URL 없음: 준비 중 팝업을 여는 버튼

## 접근성과 안전

- 외부 링크에는 `target="_blank"`와 `rel="noreferrer"`를 적용한다.
- 준비 중 요소는 실제 `<button>`을 사용해 키보드로도 실행할 수 있게 한다.
- 각 링크의 접근 가능한 이름에는 프로젝트 제목과 버튼 목적을 포함한다.

## 검증

- 렌더링 테스트에서 네 개의 GitHub URL을 확인한다.
- Trading과 수요 예측의 배포 URL을 확인한다.
- 영화 예매와 북스토어에 준비 중 버튼이 렌더링되는지 확인한다.
- 모든 외부 링크의 새 탭 및 안전 속성을 확인한다.
- 전체 테스트와 GitHub Pages 정적 빌드를 다시 실행한다.
